# Интерактивное свадебное приглашение

Готовый адаптивный сайт. Дизайн: айвори, бордовый бархат, оливковый и читаемая кириллическая антиква Cormorant Garamond для имён. Все изображения, видео и шрифты находятся локально в `dist/assets`.

## Запуск

Установленный Node.js 20+; дополнительных npm-зависимостей нет.

```sh
npm run dev
```

Откройте URL, который напечатает сервер (по умолчанию http://127.0.0.1:4173), и добавьте ID приглашения: `http://127.0.0.1:4173/3`. Корневой путь использует `backend.defaultId` из `dist/content.json`.

## Публикация на Vercel

Конфигурация `vercel.json` указывает папку `dist` как готовый статический сайт и направляет прямые адреса приглашений, например `/3`, на `index.html`. Дополнительная команда сборки не требуется.

## Поведение

- На первом экране видна только коробочка: без надписей, хедера, монограмм, музыки и навигации. Прокрутка заблокирована.
- Нажатие на коробочку запускает 10-секундную сцену: мужская рука входит слева, открывает коробочку, достаёт кольцо. Прокрутка открывается после этого момента.
- После этого движение управляется прокруткой, в том числе назад. Следующая сцена надевает кольцо на женскую руку; финальная приближает камеру и превращает кольцо в обручальное, следуя Blender-референсу.
- Доступны пропуск, повторный просмотр и опциональная тихая оригинальная мелодия, синтезируемая в браузере после нажатия.
- Учитывается системная настройка уменьшения движения; при ней показывается статичная финальная сцена.
- Календарь построен по реальному месяцу из данных, с понедельника; выбранный день обведён сердечком. Скачивание в ICS; время преобразовано из Asia/Bishkek в UTC.
- Демоформа валидирует имя/участие и сохраняет один ответ локально. Она явно сообщает, что ответ не отправлен организаторам. Реальная отправка пока не подключена.

## Данные и Xano

Сайт берёт числовой ID из пути (`/3`) и выполняет GET к `backend.baseUrl/3`. Из Xano подставляются имена, дата, программа на русском и кыргызском, тип и название места, адрес. Дата Xano без смещения трактуется как время Бишкека (`+06:00`); срок RSVP вычисляется за 14 дней до свадьбы. Неизвестный ID показывает понятное сообщение вместо чужих данных. `dist/_redirects` сохраняет работу прямых ссылок на статическом хостинге.

`dist/content.json` остаётся источником текстов и безопасным резервным шаблоном. Для приглашения с числовым ID форма сначала получает свежую запись через GET, добавляет объект `{ name, wish, guests_count, is_attending }` в массив `guests`, затем отправляет полный объект через `PATCH /priglosi/{id}/full`. Список ответов доступен по адресу `/{id}/guests`. Нельзя размещать API-ключи в `content.json` или `dist`.

## Медиа и расходы

- Четыре исходных изображения созданы встроенным Imagegen; полные промпты — `production/image-prompts.md`.
- Три видео по 10 секунд созданы через **Higgsfield / Kling 3.0 Pro image-to-video** с начальным и конечным кадрами. Промпты каждого ролика сохранены в `production/*-prompt.txt`.
- Сделано ровно три успешных платных запроса. Резерв по опубликованной максимальной базовой ставке $0.168/с: **$5.04**, лимит пользователя **$10**. Это верхняя оценка, а не выписка биллинга; скидки аккаунта могут снизить сумму. Источник: https://open.higgsfield.ai/models/kling-video/v3.0/pro/image-to-video/playground
- Рабочие ID и статусы запросов лежат локально в игнорируемой папке `production/jobs/`. Ключ читается только из внешнего файла, путь передаётся переменной `HF_ENV_PATH`. Ключ не копируется в проект и не публикуется.
- `scripts/higgsfield.mjs` запрещает дубликаты имён запросов и превышение лимита по резерву. После неоднозначной ошибки отправки нельзя удалять запись и повторять запрос без проверки результата в Higgsfield.
- Видео оптимизированы в 720×1280 H.264, 24fps, ключевой кадр каждые 6 кадров, faststart; суммарно около 8.7 MB. Это обеспечивает быстрые переходы при скролле. Исходные MP4 сохраняются локально в `production/`.

## Проверки

```sh
npm run check
```

Проверяются разбор ID из URL, преобразование ответа Xano, границы скролла и стык роликов, календарь/високосный год, часовой пояс ICS, наличие всех медиа и отсутствие клиентских секретов. Визуальная проверка выполняется в браузере. Это не тест на физическом iPhone; поведение iOS Safari следует дополнительно проверить перед рассылкой гостям.

## Структура

- `dist/` — весь сайт для любого статического хостинга.
- `dist/content.json` — адрес backend и резервные тексты приглашения.
- `dist/backend-adapter.js` — проверка и преобразование ответа Xano.
- `dist/app.js` — проигрывание, скролл, форма, календарь и звук.
- `dist/story-model.js` — расчёт сцены и календаря.
- `scripts/` — локальный предпросмотр, проверки, подготовка ассетов и Higgsfield.
- `.openai/hosting.json` — сохранённый идентификатор приватного Sites-проекта.

Ориентир структуры: https://golden-butterfly-template.vercel.app/ . Фотографии и анимации созданы для этого проекта; материалы исходного сайта не копировались.
